# Accuracy benchmark

A small, pinned set of repositories with hand-written expected results. It
measures whether Cartographer extracts the relationships a reader would find in
the source, and it runs in CI as a regression check.

```sh
uv run --no-sync python scripts/benchmark.py          # results table
uv run --no-sync python scripts/benchmark.py --json   # full report, including each miss
uv run --no-sync python scripts/benchmark.py --check  # exit 1 on any regression
```

Known gaps:

- tsconfig path aliases such as `@/utils/log` are not resolved, so those imports
  produce no edge.
- SQL constants imported from another Python module are not resolved.
- f-string SQL is reported as dynamic, even when only values are interpolated.

These corpora are small and were chosen to exercise specific cases. The numbers
show behavior on those cases; they are not an estimate of accuracy on arbitrary
repositories.

## Method

- Expected facts in `expected/<corpus>.json` were written by reading the corpus
  source, not by copying analyzer output.
- Each corpus is analyzed in a temporary copy, so no artifacts are written here.
- **imports**: static module dependencies as `importer -> imported module`,
  resolved to repository files. Edges to package `__init__.py` files listed in
  `ignore_import_targets` are neither required nor penalized.
- **functions**: top-level functions and class methods as `path::qualified.name`.
  Nested functions are not scored.
- **lineage**: dataset dependencies as `source -> target`, derived from each
  transformation's consumed and produced datasets.
- Precision is correct facts divided by facts reported. Recall is correct facts
  divided by expected facts.
- `--check` fails on any false positive, any miss not listed in `known_gaps`, any
  listed gap that is now found, and any unexpected run status (`complete` or
  `partial`).

The vendored jaffle_shop copy keeps only the files relevant to analysis. Images
and repository metadata were omitted.

## Adding a corpus

1. Add the source under `corpora/<name>/`. Use a small, licensed repository
   pinned to a commit and include its license, or write a focused fixture.
2. Write `expected/<name>.json` by reading the source. Include `status` and any
   of `imports`, `functions`, and `lineage`.
3. Record unsupported cases under `known_gaps` with a reason, rather than
   removing them from the expected facts.
4. Run `scripts/benchmark.py --check` and update the results table above.
